## 📡 1. Расширенный технический радар

**Файл:** [tech-radar.md](tech-radar.md)  
**Визуализация:** ![Tech Radar](tech-radar.drawio.png)  
**Исходник:** [tech-radar.drawio](tech-radar.drawio) *(открыть на [app.diagrams.net](https://app.diagrams.net/))*

Радар классифицирует технологии и архитектурные подходы по 4 квадрантам:

| Статус | Значение | Примеры из радара |
| :--- | :--- | :--- |
|  **Adopt** | Принять — корпоративный стандарт | Event-Driven Architecture, Terraform, Go, Yandex MK8s, PostgreSQL |
| 🟡 **Trial** | Опробовать — пилоты и масштабирование | Data Mesh, Self-service BI (DataLens), Yandex Message Queue |
|  **Assess** | Оценить — перспективные, требуют PoC | CQRS, Serverless Functions, Data Lakehouse (ClickHouse) |
| 🔴 **Hold** | Удерживать/отказаться — вывод из эксплуатации | Apache Camel ESB, Legacy DWH, Nightly ETL, PHP/Java Monolith |

**Ключевые выводы:**
- Переход от централизованной ESB (Camel) к децентрализованной событийной шине (Yandex MQ)
- Отказ от монолитного DWH в пользу Data Mesh + Stream Processing
- Инфраструктура как код (Terraform) — обязательный стандарт для всех новых проектов

##  2. Экономическое обоснование (TCO)

**Файл:** [tco-analysis.md](tco-analysis.md)

Модель Total Cost of Ownership сравнивает текущую и целевую архитектуру на горизонте **3 лет** по 5 статьям затрат: инфраструктура, лицензии, сопровождение, время аналитиков, стоимость простоев.

**Главные инсайты:**

| Показатель | Значение |
| :--- | :--- |
| **Год 1** | Рост затрат на +13% (параллельная поддержка legacy + новой системы) |
| **Год 2** | Точка безубыточности — затраты снижаются на 22% |
| **Год 3** | Экономия **30-40%** относительно текущей архитектуры |
| **Накопительная экономия за 3 года** | ~3 150 тыс. руб. (в условных единицах модели) |

**Драйверы экономии:**
1. Отключение дорогостоящих legacy-лицензий (DWH, ESB)
2. Автоматизация через IaC (Terraform) и CI/CD (GitHub Actions)
3. Self-service BI высвобождает 40% времени аналитиков
4. Повышение SLA с 95% до 99.9% снижает потери от простоев

## 🗺️ 3. Стратегический роадмап Data Mesh

**Файл:** [roadmap.md](roadmap.md)

План трансформации на **18 месяцев**, разделённый на 4 фазы:

| Фаза | Сроки | Ключевые роли | Домены | Бизнес-цель |
| :--- | :--- | :--- | :--- | :--- |
| **1. Foundation & Pilot** | Мес. 1-3 | Platform Team, DPO (Patients) | Пациенты | Быстрый win, доказательство концепции |
| **2. Expansion** | Мес. 4-9 | DPO (Contract, Billing), BI-аналитики | Договоры, Биллинг | Сокращение Time-to-Insight в 10 раз |
| **3. Scaling & AI** | Мес. 10-14 | DPO (Research), Data Scientists | Исследования, AI/ML | Персонализация, +25% конверсии |
| **4. Optimization & Sunset** | Мес. 15-18 | Все роли, FinOps | Все + Legacy | Экономия 30% TCO, compliance 152-ФЗ |

**Ключевые роли в Data Mesh:**
- **Data Product Owner (DPO)** — владелец качества и ценности данных в домене
- **Domain Data Engineer** — строит пайплайны и витрины внутри домена
- **BI-аналитик (Consumer)** — потребитель данных через Self-service BI
- **Data Platform Team** — обеспечивает инфраструктуру и стандарты
- **Data Governance Lead** — политики, метаданные, compliance

**Итоговые KPI (к 18-му месяцу):**
- Time-to-Insight: 2 недели → 2 дня (**-85%**)
- Инциденты качества данных: **-80%**
- Доля self-service отчётов: 10% → 70% (**+60 п.п.**)
- TCO: **-30%**
- Соответствие 152-ФЗ: **100%**
